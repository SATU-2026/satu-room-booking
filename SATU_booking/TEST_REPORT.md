# ผลตรวจชุดไฟล์

## ผ่านการตรวจแล้ว

- JavaScript syntax: core.js, api.js, app.js, config.js, data.js
- กติกาเวลา: จองล่วงหน้า 5 วัน วันเดียวกัน เวลาสิ้นสุดต้องหลังเริ่ม และยกเลิกก่อนเริ่มอย่างน้อย 1 ชั่วโมง
- ช่วงเวลาซ้อนทุกรูปแบบ และอนุญาตช่วงติดกัน 09.00–11.00 / 11.00–12.00
- โหมด demo: สร้างคำขอ ส่งซ้ำคืนรายการเดิม ห้ามเวลาซ้อน แยกเจ้าหน้าที่ตามศูนย์ ห้ามเจ้าหน้าที่กดอนุมัติแทนหัวหน้า
- โหมด demo: เจ้าหน้าที่ตรวจ → หัวหน้าอนุมัติ → ผู้จองแก้รายละเอียดแล้วกลับรอตรวจ โดยยังกันห้อง
- โหมด demo: ยกเลิก/ไม่อนุมัติคืนห้อง ปิดห้องชนรายการเดิมต้องถูกปฏิเสธ เหตุผลห้ามว่าง
- SQL schema/seed ใช้งานได้ใน PGlite (embedded PostgreSQL) พร้อม pgcrypto และ btree_gist; จำลอง Supabase Auth roles และ storage.buckets สำหรับการทดสอบ
- RPC จริงใน PostgreSQL จำลอง: idempotency, exclusion constraint, เวลาติดกัน, ไม่ให้ anon อ่านตารางโดยตรง, รหัสผิดเปิดรายละเอียดไม่ได้
- RPC: lookup ไม่คืนชื่อ/เบอร์/hash, ข้ามศูนย์ไม่ได้, ตรวจ/อนุมัติแยกบทบาท, ยกเลิกและจองใหม่, การปิดห้อง, สิทธิ์ไฟล์ และการตั้งค่าห้อง/ผู้ประสานงาน/สิทธิ์โดยแอดมิน
- Browser QA บน Chrome: หน้าปฏิทิน/ฟอร์มแสดงผล ส่งคำขอสมมติ ค้นหาเบอร์ เปิดรายละเอียดด้วยรหัส ยกเลิกและเห็นประวัติ และบัญชีสาธิตท่าพระจันทร์เห็นเฉพาะรายการศูนย์ของตน

## ขอบเขตการตรวจ

ยังไม่เชื่อมโครงการ Supabase หรือ repository ของผู้ใช้ จึงยังไม่ได้ทดสอบ hosted Auth, การส่ง JWT ผ่าน Data API, Edge Function/Storage upload/download และการแข่งขันของธุรกรรมจากผู้ใช้สองเครื่องบนบริการจริง
ไม่ได้ load test ไม่ได้ย้ายฐานข้อมูล MySQL และไม่ได้เผยแพร่ GitHub Pages
การตรวจ SQL จำลองไม่เท่ากับการผ่าน end-to-end บน Supabase จริง
ไม่มีการใส่ข้อมูลบุคคลจริงหรือรหัสผ่านจริงในชุดไฟล์

## รันซ้ำ

ไม่ต้องติดตั้ง dependency เพื่อเปิดเว็บ demo
สำหรับผู้พัฒนาที่ต้องการตรวจซ้ำ:

```bash
node tests/core.test.cjs
node tests/demo.test.cjs
npm install
node tests/sql.test.mjs
```

`npm install` ใช้เฉพาะการทดสอบ SQL; ไม่จำเป็นสำหรับ GitHub Pages
