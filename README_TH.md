# ระบบจองห้องและสถานที่ กองกิจการนักศึกษา มธ.

เวอร์ชันปรับจากต้นแบบรังสิต สำหรับ GitHub Pages + Supabase
รองรับศูนย์รังสิตและท่าพระจันทร์ ใช้กติกาเดียวกัน แยกเจ้าหน้าที่ตามศูนย์

## 1. เปิดดูและทดลองทันที

1. แตกไฟล์ ZIP ออกก่อน
2. เปิด `index.html` ด้วย Chrome หรือ Edge
3. ระบบเริ่มในโหมด **demo** ไม่ต้องติดตั้ง PHP หรือฐานข้อมูล
4. เลือกศูนย์ ดูปฏิทิน จองห้อง และทดลองติดตามคำขอ
5. กด **สำหรับเจ้าหน้าที่** แล้วเลือกบทบาทสาธิต

บัญชีสาธิตมีเจ้าหน้าที่รังสิต เจ้าหน้าที่ท่าพระจันทร์ หัวหน้าดูแลสองศูนย์ และแอดมิน
รายการตัวอย่างอยู่วันที่ 6 วันถัดจากวันที่เปิดครั้งแรก ค้นหาด้วยเบอร์ `0800000000` และรหัส `DEMO1234`
รายการที่สร้างใหม่จะได้รหัสสุ่มเฉพาะของตนเอง พร้อมปุ่มคัดลอกและบันทึกเป็นไฟล์ข้อความ

**ข้อมูล demo เก็บในเบราว์เซอร์นี้เท่านั้น ไม่ส่งไป Supabase และไม่ใช่การจองจริง**
กรุณาใช้ข้อมูลสมมติ ห้ามนำโหมดนี้ไปเปิดรับจองจริงหรือใช้เป็นหลักฐานยืนยันสิทธิ์
หากเปิดไฟล์ตรงแล้วเบราว์เซอร์ปิดกั้นที่เก็บข้อมูล ให้เปิดด้วย VS Code Live Server หรือ GitHub Pages
โหมดสาธิตแนบไฟล์ได้ แต่พื้นที่ localStorage มีจำกัด เหมาะกับไฟล์เล็ก การเกินพื้นที่จะมีข้อความแจ้งและคำขอที่สำเร็จแล้วไม่ถูกลบ

## 2. แก้หน้าตาและรายชื่อห้องที่ไหน

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าเว็บ หัวเรื่อง เมนู ข้อความกติกา |
| `styles.css` | สี ตัวอักษร และหน้าตาบนมือถือ |
| `data.js` | รายชื่อศูนย์ ห้อง และผู้ประสานงานของโหมด demo |
| `config.js` | เลือก demo/live และค่าการเชื่อม Supabase |
| `core.js` | กติกาเวลา การทับซ้อน และการแยกสิทธิ์ที่หน้าเว็บ |
| `api.js` | ส่วนข้อมูล demo และตัวเชื่อม Supabase |
| `app.js` | ปฏิทิน แบบฟอร์ม การติดตาม หน้าจัดการ |
| `supabase/` | SQL ฐานข้อมูล สิทธิ์ และ Edge Function สำหรับไฟล์ |

รังสิตมี 8 สถานที่ตามไฟล์เดิม ความจุเว้นว่างเพราะต้นฉบับไม่ได้ยืนยัน
ท่าพระจันทร์มีห้องตัวอย่าง 3 ห้อง ความจุ 20/40/60 คนเป็นข้อมูลสมมติ
เปลี่ยน `name` / `capacity` / `contact_name` / `contact_phone` ใน `data.js` ได้
อย่าเปลี่ยน `id` ของห้องที่มีการจองแล้ว เพราะเป็นตัวเชื่อมรายการเก่า
เมื่อแก้ `data.js` แล้วรีเฟรช ชื่อ/ข้อมูลต้นแบบที่เปลี่ยนจะถูกนำเข้าใหม่ โดยยังเก็บรายการทดลองเดิม
แก้ผ่านหน้า **แอดมิน > ตั้งค่าระบบ** ได้เช่นกัน; การแก้ไฟล์ต้นแบบครั้งถัดไปจะทับค่าห้องต้นแบบที่มี ID ตรงกัน

**ในโหมด live รายชื่อห้องและผู้ประสานงานมาจาก Supabase** ให้แก้ผ่านหน้าแอดมิน ไม่ใช่ `data.js`

## 3. ขั้นตอนและกติกาที่ใส่ไว้

- ผู้จองไม่ต้องสมัครบัญชี เลือกศูนย์ ห้อง วันที่ เวลาเริ่ม–สิ้นสุด และกรอกข้อมูล
- จองล่วงหน้าอย่างน้อย 5 วัน นับตามวันที่ไทย เวลาเริ่ม–สิ้นสุดอยู่วันเดียวกันและสิ้นสุดหลังเริ่ม
- ใช้เวลาตามจริง ไม่บังคับจองแยกทีละชั่วโมง และจองติดกัน เช่น 09.00–11.00 แล้ว 11.00–12.00 ได้
- ส่งสำเร็จแล้วกันห้องทันทีในสถานะ **รอตรวจสอบ**
- เจ้าหน้าที่ศูนย์ตรวจผ่าน → **รอหัวหน้าอนุมัติ** → หัวหน้ากด **อนุมัติแล้ว**
- เจ้าหน้าที่/หัวหน้าปฏิเสธคำขอได้ในช่วงรอตรวจหรือรออนุมัติ โดยต้องให้เหตุผล
- เจ้าหน้าที่และหัวหน้ายกเลิกรายการในศูนย์ที่ได้รับสิทธิ์ได้ พร้อมเหตุผล
- ยกเลิกหรือไม่อนุมัติแล้วช่วงเวลาว่างทันที เก็บรายการและประวัติไว้ ไม่ลบทิ้ง
- ผู้จองยกเลิกเองได้ถึงก่อนใช้งาน 1 ชั่วโมง หลังจากนั้นติดต่อเจ้าหน้าที่
- ผู้จองแก้รายละเอียดกิจกรรม/จำนวนผู้เข้าร่วม และแนบเอกสารได้ก่อนเริ่มใช้งาน
- ไม่ให้เปลี่ยนศูนย์ ห้อง วัน หรือเวลา ถ้าต้องการเปลี่ยนให้ยกเลิกและจองใหม่
- การแก้รายละเอียดหรือแนบเอกสารใหม่จะกลับไปรอตรวจสอบ โดยยังกันห้องเดิมไว้
- คำขอรอตรวจไม่หมดอายุอัตโนมัติ เจ้าหน้าที่จัดการตามคิวเอง
- เกินความจุห้องแสดงข้อความประกอบการพิจารณา ไม่ปฏิเสธอัตโนมัติ
- บันทึกเวลาเป็น UTC และแสดงผลด้วย Asia/Bangkok
- ปฏิทิน/หน้าจัดการโหลดใหม่เมื่อเปิดหน้า เปลี่ยนตัวกรองช่วงเดือน และทุก 60 วินาทีเมื่อเปิดหน้านั้นอยู่โดยไม่มีหน้าต่างฟอร์ม

### สี่เรื่องที่เพิ่มล่าสุด

1. **ปิดห้องเฉพาะช่วง:** เจ้าหน้าที่/แอดมินเลือกห้องและช่วงวันเวลา รวมหลายวันได้ พร้อมเหตุผล ถ้ามีรายการชนจะแจ้งเลขคำขอและไม่บันทึกช่วงปิดจนกว่าจะจัดการรายการเดิม ไม่ยกเลิกคำขอเก่าอัตโนมัติ
2. **กดส่งซ้ำ:** ล็อกปุ่มระหว่างส่ง และใช้ idempotency key ที่ฐานข้อมูล การส่งคำขอเดิมซ้ำจะได้รายการเดิม กรณีคนละคำขอจองซ้อนกันฐานข้อมูลปฏิเสธด้วย exclusion constraint
3. **เหตุผล:** ไม่อนุมัติ/ยกเลิกโดยเจ้าหน้าที่ต้องระบุเหตุผล ผู้จองอ่านได้หลังกรอกรหัสจัดการ และมีประวัติผู้ดำเนินการ/เวลา
4. **ติดต่อ:** แสดงผู้ประสานงานตามศูนย์ ใส่ชื่อและเบอร์ placeholder ไว้ ย้ำค้นหาด้วยเบอร์โทร และแก้ไข/ยกเลิกด้วยรหัสจัดการ

### ความหมายของข้อมูลที่เปิดดูได้

- ปฏิทินสาธารณะเห็นห้อง เวลา สถานะ และจำนวนรายการ ไม่มีชื่อ เบอร์โทร หรือเอกสาร
- ค้นหาเบอร์เต็มเห็นเลขคำขอ ศูนย์ ห้อง เวลา สถานะ ไม่เปิดข้อมูลผู้จองและเหตุผลส่วนตัว
- ต้องมีรหัสจัดการจึงเปิดรายละเอียด/เอกสาร แก้ไข หรือยกเลิกได้
- เบอร์โทรเป็นตัวค้นหา **ไม่ใช่การพิสูจน์ว่าเป็นเจ้าของเบอร์** ตามรูปแบบที่ตกลงไว้
- ลืมรหัสให้ติดต่อเจ้าหน้าที่เพื่อตรวจสอบก่อนช่วยดำเนินการ ไม่มีการเปิดเผยรหัสเดิมหรือกู้รหัสด้วยเบอร์โทรอย่างเดียว
- รหัส live เก็บเป็น SHA-256 ในฐานข้อมูล ไม่เก็บรหัสจริง; รหัส demo เป็นข้อมูลจำลอง
- ยังไม่มีอีเมล/LINE/SMS แจ้งเตือนอัตโนมัติ ผู้จองตรวจสถานะเอง

## 4. เชื่อม Supabase เพื่อทดลองระบบจริง

ชุดไฟล์มีส่วนเชื่อมต่อให้แล้ว แต่ยังไม่ได้ติดตั้งในโครงการ Supabase ของคุณ
ควรเริ่มด้วยโครงการทดสอบแยกจากปฏิทินเดิม เพื่อทดลองครบทุกบทบาทก่อนรับจองจริง

1. เปิด SQL Editor ของโครงการ Supabase ที่จะใช้
2. รัน `supabase/01_schema.sql` **ครั้งเดียว** เพื่อสร้างตาราง RPC และสิทธิ์
3. รัน `supabase/02_seed.sql` เพื่อเพิ่มสองศูนย์และห้อง รายการจองตัวอย่างจะไม่ถูกนำเข้า
4. เปิด Authentication > Users สร้างบัญชีแอดมินด้วยอีเมล/รหัสผ่านของคุณ
5. คัดลอก User UID ไปแทน `YOUR-USER-UUID` ใน `supabase/03_first_admin.sql` แล้วรัน
6. ใน `config.js` ใส่ค่าจริง:

```javascript
window.BOOKING_CONFIG = {
  mode: 'live',
  supabaseUrl: 'https://YOUR-PROJECT.supabase.co',
  supabasePublishableKey: 'YOUR-PUBLISHABLE-KEY',
  fileFunction: 'booking-files'
};
```

ใช้ Publishable key หรือ legacy anon key สำหรับหน้าเว็บเท่านั้น
**ห้ามใส่ secret/service_role key ใน config.js, HTML, JavaScript หรือ GitHub**

7. เข้าสู่หน้าเว็บ > สำหรับเจ้าหน้าที่ ด้วยอีเมลแอดมิน
8. สร้างบัญชีเจ้าหน้าที่/หัวหน้าใน Supabase Authentication แล้วนำ UID ไปกำหนดผ่านหน้าเว็บ > ตั้งค่าระบบ > กำหนดสิทธิ์
9. หัวหน้าคนเดียวดูแลสองศูนย์ได้: ใส่ UID เดิมสองครั้ง แยกเลือกศูนย์รังสิตและท่าพระจันทร์ หากมีหัวหน้าสองคนให้ใช้คนละ UID
10. เปลี่ยนผู้ประสานงานและรายชื่อ/ความจุห้องให้ถูกต้อง

ห้องท่าพระจันทร์ในฐานข้อมูล live **เริ่มเป็นปิดรับจอง** เพื่อไม่ให้ห้องสมมติถูกจองจริง แอดมินเปิดได้เมื่อพร้อม
SQL ใช้ชื่อตารางขึ้นต้น `bkg_` ไม่แก้ตารางของระบบปฏิทินเดิม
สิทธิ์แยกศูนย์บังคับใน RPC ฝั่งฐานข้อมูล ไม่ได้อาศัยการซ่อนปุ่มบนหน้าเว็บ
ไม่เปิดการอ่านตารางข้อมูลส่วนตัวโดยตรงให้ anon/authenticated

## 5. เปิดใช้เอกสารแนบใน Supabase

เอกสารเป็นไฟล์ส่วนตัว เก็บใน bucket `booking-files` ที่ไม่เปิด public
ต้อง deploy Edge Function ชื่อ `booking-files` ด้วย จึงจะใช้งานไฟล์ในโหมด live ได้

จากโฟลเดอร์ชุดไฟล์นี้ เมื่อมี Supabase CLI:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy booking-files --no-verify-jwt
```

`supabase/config.toml` กำหนด verify_jwt=false เพราะผู้จองไม่มีบัญชี แต่ฟังก์ชันตรวจรหัสคำขอหรือ JWT ของเจ้าหน้าที่เองก่อนอ่าน/เขียนทุกครั้ง
SUPABASE_URL, SUPABASE_ANON_KEY และ SUPABASE_SERVICE_ROLE_KEY ใช้จาก environment ของ Edge Function ไม่ส่งไปหน้าเว็บ
หาก deploy ผ่าน Dashboard ให้ใช้โค้ด `supabase/functions/booking-files/index.ts` และตั้ง Verify JWT ให้สอดคล้องกับ config
ไฟล์รองรับ PDF/JPG/PNG ตรวจ signature ไม่เกิน 5 MB/ไฟล์ สูงสุด 3 ไฟล์ต่อคำขอ
ลิงก์ดาวน์โหลดมีอายุ 60 วินาที และต้องผ่านการตรวจสิทธิ์ก่อนออกลิงก์
หากจองสำเร็จแต่แนบไฟล์ไม่สำเร็จ ระบบแสดงรหัสคำขอให้เก็บไว้และแจ้งให้แนบใหม่จากหน้าติดตาม ไม่ส่งคำขอใหม่ซ้ำ

## 6. อัปโหลด GitHub Pages

- สร้าง repository สำหรับระบบจองนี้
- อัปโหลด `index.html`, `styles.css`, `config.js`, `data.js`, `core.js`, `api.js`, `app.js` และโฟลเดอร์ `assets/` ไว้ระดับบนสุดของ repository
- อย่าอัปโหลด ZIP ทั้งก้อนแทนไฟล์เว็บ
- เพิ่มไฟล์ `.nojekyll` ที่ให้มาด้วย
- ใน Settings > Pages เลือก Deploy from a branch > main > /(root)
- เส้นทางไฟล์ทั้งหมดเป็น relative ใช้ได้กับ URL แบบ username.github.io/repository/
- สามารถเผยแพร่เพื่อดู demo ก่อน แล้วค่อยแก้ config.js เป็น live หลังตั้ง Supabase ครบ

ชุดนี้เขียนหน้าเว็บใหม่จากแนวทางระบบเดิม ไม่ใช้ PHP runtime และไม่ย้ายข้อมูล MySQL เก่าเข้ามาอัตโนมัติ
ไม่รวมไฟล์เชื่อมฐานข้อมูล/รหัสผ่านจาก PHP เดิมในเว็บไซต์ใหม่

## 7. สิ่งที่ต้องทดสอบบน Supabase ก่อนเปิดรับจองจริง

ดูรายละเอียดที่ `TEST_REPORT.md`
โค้ดหน้าเว็บและ RPC ผ่านการตรวจตามรายงานแล้ว แต่ Supabase Auth, Edge Function/Storage และ GitHub Pages ของคุณยังไม่ได้เชื่อมในรอบนี้
ทดลองล็อกอินแต่ละบทบาท สองเครื่องจองช่วงเดียวกัน แนบ/อ่านไฟล์ส่วนตัว เปลี่ยนสถานะ และยกเลิกแล้วจองใหม่บนโครงการทดสอบจริง
RPC มี rate limit เริ่มต้นค้นหา 30 ครั้ง/นาที และสร้างคำขอ 10 ครั้ง/นาทีต่อ IP (fallback เป็น shared หาก proxy ไม่ส่ง IP) ควรปรับและทดสอบให้เหมาะกับเครือข่ายมหาวิทยาลัยที่อาจใช้ IP ร่วมกันก่อนเปิดจริง
ยังไม่ได้ตั้ง CAPTCHA, ระบบแจ้งเตือน, งานสำรองข้อมูลอัตโนมัติ หรือการย้ายประวัติจาก MySQL
